The Customer API lets you read and update customer profiles stored in Tilroy in real time. Use it to keep your webshop account records, loyalty platform, or CRM in sync with Tilroy's customer data — or to let customers update their own information directly from your app or storefront.

## Authentication for the Customer API

The Customer API requires three headers on every request:

```http request.http
GET https://api.tilroy.com/customerapi/production/customers/{customerId}
x-api-key: <your-profile-key>
Tilroy-Api-Key: <your-account-key>
Authorization: Bearer <token>
```

| Header | Description |
|---|---|
| `x-api-key` | Your profile key — controls API access and permissions. |
| `Tilroy-Api-Key` | Your account identifier. Use your ACC key for acceptance testing and your PROD key for production. |
| `Authorization: Bearer <token>` | A bearer token scoped to the customer (or a service-level token for full sync). |

## Bearer Tokens

Tilroy supports two bearer token strategies depending on your use case:

<Tabs>
  <Tab title="Per-Customer Token">
    Use this approach when your application acts on behalf of a specific logged-in customer — for example, letting a customer view or edit their own profile in your webshop.

    <Steps>
      <Step title="Call the Authentication API">
        POST to `/tokens` on the Authentication API, providing the customer's credentials. See the [Authentication API](/api-reference/authentication-api) page for details.
      </Step>
      <Step title="Receive a bearer token">
        The Authentication API returns a token scoped to that specific customer.
      </Step>
      <Step title="Pass the token on Customer API requests">
        Include the token as `Authorization: Bearer <token>` on every Customer API call for that customer.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Service-Level Token">
    Use this approach for background integrations that need to read or update **all** customer records — for example, a nightly sync between Tilroy and your CRM or loyalty platform.

    Contact [integrations@tilroy.com](mailto:integrations@tilroy.com) to request a service-level token. This token is not customer-scoped and can be used across all customer records in your account.
  </Tab>
</Tabs>

<Warning>
  If you receive the error **"User xxx has no permission to update customer"**, the bearer token and `Tilroy-Api-Key` belong to different tenants. Ensure that both values come from the same Tilroy account (ACC or PROD). Mixing keys from different accounts will always result in this error.
</Warning>

## Synchronous API

The Customer API is **synchronous** — every request is handled in real time and returns an immediate response. There is no queue or async processing. This makes it suitable for live customer-facing flows where latency matters.
